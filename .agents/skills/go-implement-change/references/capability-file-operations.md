# 文件操作能力

仅当已批准的核心闭环读取或写入文件时使用本指引。本参考的存在不代表每个已初始化项目都具有文件操作能力。

## 范围闸门

实施前必须确认以下全部事实：

- 产品规格已明确文件或目录输入/输出。
- 已明确区分只读和变更行为。
- 已定义覆盖、冲突、部分写入、权限和恢复行为。
- 最高风险数据丢失路径具有可观察的预期结果。

如果这些事实尚未解决，必须停止并返回 `$go-define-product`。

## 边界

- 跨越核心边界的路径必须使用 `path/filepath` 的 `filepath.Join`、`filepath.Clean`、`filepath.Abs` 等平台感知的路径 API；不得假设 UTF-8，也不得手动拼接路径分隔符或硬编码 `/`、`\`。
- 领域验证和覆盖策略属于核心。
- 文件读写的具体驱动可位于适配器或基础设施模块，但何时读取/写入、内容如何解释、冲突如何影响领域状态以及失败如何映射为稳定领域错误属于核心；不得在每个适配器中重复实现同一文件业务流程。
- 用户提示、确认标志、JSON 渲染和退出码映射属于适配器。
- 同步 I/O 是默认选择（`os`、`io`、`bufio`）；只有在已批准行为确实需要并发或可取消时才引入 `context.Context` 与 goroutine，并保证取消后不留悬挂写入。
- 在至少存在两个实现或一个具体可测试性问题前，不得增加文件系统抽象接口。

## 变更安全

- 当产品可以采取不同处理方式时，读取必须区分未找到（`os.IsNotExist`/`errors.Is(err, fs.ErrNotExist)`）、权限被拒绝（`fs.ErrPermission`）、输入无效和内容格式错误。
- 未经明确批准的策略和 CLI 标志，写入不得覆盖现有目标。
- 如果部分输出会造成损害，必须先写入同级临时文件（`os.CreateTemp(dir, ...)`），按照产品可靠性目标完成必要的 `Sync()` 与 `Close()`，并且仅在成功后用 `os.Rename` 原子替换目标。
- 清理不得递归作用于未解析变量、宽泛目录或已批准操作范围之外的路径；删除前必须确认路径已解析且位于批准范围内。
- 错误消息和 JSON 详情不得暴露不必要的绝对宿主路径。

## 必需验证

- 为已批准的文件转换或验证提供核心成功路径测试。
- 提供最高风险失败测试，通常覆盖冲突、部分写入、无效内容或权限失败。
- 为 JSON 输出、标准错误分流和稳定退出码提供 CLI 黑盒测试。
- 跨平台测试必须使用平台 API 构造路径（`filepath.Join`、`t.TempDir()`）。未经测试的平台必须保持 `Unverified`。
- 变更型验收测试只能在隔离的临时目录（`t.TempDir()`）中运行，并且必须同时验证输出和原有数据得到保留。

## 退出条件

如果产品不再读取或写入文件，必须删除该能力专用的依赖、测试和代码。仅保留继承自 Harness 的通用路径和数据丢失规则。
