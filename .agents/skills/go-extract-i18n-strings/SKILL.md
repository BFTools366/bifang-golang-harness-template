# 抽取硬编码文案为 i18n 配置

把适配器中硬编码的用户可见文案迁移为 ADR-20260806-001 固定的 i18n 技术栈键值，不新建并行的国际化机制，也不触碰 core 的业务判定。

## 工作流程

1. 确认当前项目已接入 `internal/pkg/i18n`（词条位于 `internal/pkg/i18n/locales/{zh-CN,en-US}.yaml`）且配置中 `i18n.enabled: true`、`i18n.fallback: zh-CN`、`i18n.support` 已声明支持语言，可在 `docs/GO_WEB_TEMPLATE.md` 第 11 节核对固定技术栈；未接入时先完成基础接入，不在中途新建替代机制。
2. 直接实施不改变默认语言下可观察行为的纯文案迁移；若同时新增语言协商入口或修改默认语言探测逻辑，先确认产品边界，只在形成长期重要决定或硬规则例外时记录 ADR。
3. 扫描范围限定在适配器侧：`internal/api/**/*.go` 与 `internal/middleware/**/*.go` 中直接写给最终用户的字符串（handler 内拼装的错误提示、`response` 调用旁的中文常量）。绝不扫描或修改共享 core 的业务判定；core 中出现的用户可见字符串是 core-first 边界问题，转 `$go-refactor-code` 评估，不在本 Skill 内直接改写核心包。
4. 排除非用户可见字符串：标识符、结构体 tag、日志文案（logrus 字段与消息）、内部错误码常量名、测试夹具、代码注释和开发调试专用文本；只处理真实渲染给最终用户的文案。`internal/apperr` 中的 `Code` 本身就是 i18n 键，已有键不得重复抽取或改名。
5. 为每处硬编码文案生成或复用稳定的层级翻译 key（如 `settings.language.label`），沿用 `internal/apperr` 已有的「域.子域.原因」小写点分格式（例如 `order.not.found`），在 `locales/<locale>.yaml` 中以平铺 `key: 模板` 形式登记；值支持 `%s` 占位符并按顺序对应可变参数，不得把 key 直接设为源文案本身的复制。
6. 只为基准回退语言（`i18n.fallback` 声明的 `zh-CN`）和当前已批准维护的语言写入真实翻译，且每个新 key 必须在 `i18n.support` 声明支持的全部语言文件中同时存在；不得为未批准或未来语言臆造译文。缺失译文按 `docs/ENGINEERING_RULES.md` 第 3.3 节关于临时标记的规则记录明确原因和完成条件，并同步登记 `docs/TECH_DEBT.md`，不得裸写未说明原因的临时标记。
7. 替换源码中的字符串字面量为 i18n 查表调用后，运行相关 Go 测试确认默认语言渲染结果与迁移前一致；新增 key 需有测试或人工核对证据，不得只改资源文件不验证渲染。占位符数量与可变参数对不上时必须按 `docs/GO_WEB_TEMPLATE.md` 第 11 节回落到 `Message` 兜底模板，不得输出 `%!s(MISSING)`。
8. 仅对本次触及文件执行适用硬门禁：Go 源码超过 800 行、翻译资源等其他人工维护文本超过 2000 行必须按真实职责拆分。401–800 行 Go 与 501–2000 行其他文本的职责复核只在明确发布且当次 `reviewSelection: enabled` 时集中执行；日常文案迁移不自行增加软阈值审查，也不自动运行全仓文件行数门禁。
9. 只按 `docs/ENGINEERING_RULES.md` 的独立事件触发规则更新项目记忆；纯文案迁移属于不改变可观察行为的重构，默认不触发 Product Spec、ADR、Product Status 或 Changelog。

## 硬边界

- 不得新建第二套国际化机制、内嵌第二份词条副本，或用直接拼接语言判断分支替代 `internal/pkg/i18n` 的统一查表。
- 不得触碰共享 core 的业务判定；发现 core 内的硬编码用户可见文案时停止并转交 `$go-refactor-code` 评估 core-first 边界，不在本 Skill 内跨边界改写。
- 不得臆造未批准语言的翻译内容；缺失译文必须显式记录而不是留空、复制基准语言或留待运行时暴露。
- 不得为了消除硬编码字符串而改变默认语言下的实际展示文案含义；迁移前后语义必须一致。
- 迁移不得引入新的公开路由、统一响应体形状或错误码变化；纯文案位置迁移不视为对外契约变化。新增错误码仍只改 `internal/apperr` 并同步补齐全部 locale 文件的同名 key。

## 完成输出

报告扫描范围、抽取的字符串数量与对应翻译 key、新增或修改的 locale 资源文件、跳过的字符串及原因、已记录的缺失译文技术债、运行过的测试与检查，以及默认语言渲染结果的验证方式。
