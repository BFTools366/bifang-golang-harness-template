# ADR-20260923-001：从 Rust 桌面 Harness 抽取语言无关方法论并 Go 化技术基线

## 状态

Accepted

## 关联需求

Harness 模板立项：`change_id: harness-golang-bootstrap`，`required_version: N/A`（Harness 自身使用时间版本，不使用下游 SemVer）。

## 背景

仓库 `bifang-desktop-harness-template` 已积累了一套针对 Rust + React/Tauri 桌面应用的 Harness 工程，包含七层模型方法论、文档体系、验证脚本、Agent Skills 与发布生命周期。

需要把这套方法论复用到 Go 服务端项目。已有 `golang-web-template` 提供了 Gin + GORM 的分层结构、泛型仓储、雪花 ID、统一响应体、`apperr` 错误模型与多环境配置约定。

`docs/CLI_CONTRACT.md` 明确声明「Rust 下游项目使用 `docs/RUST_CLI_TEMPLATE.md` 的默认实现与测试基线；其他语言必须提供等价行为和证据」，方法论本身也以「桌面工具、命令行工具、脚本或终端工具」为适用对象，不绑定具体语言。

## 决定

1. **骨架保留，肌肉替换。** 保留 Harness 七层模型、文档单一事实来源体系、版本管理双轨制、Git 发布生命周期、验证脚本编排骨架与 Skill 组织方式；把 Rust/Cargo/Tauri/React 专属实现替换为 Go 的等价物。
2. **新增 `docs/GO_WEB_TEMPLATE.md` 作为唯一 Rust→Go 技术基线替代。** 原 `docs/RUST_CLI_TEMPLATE.md` 不复制，`docs/design_standards/` 下 Tauri/Mantine 专属标准不复制。
3. **行数门禁由双轨简化为单轨。** 原 Rust 800 行 / 前端 1000 行 / 其他 2000 行简化为 Go 800 行 / 其他 2000 行；建议重构区间为 401–800 与 501–2000。
4. **Skills 命名前缀由 `desktop-` 改为 `go-`。** GUI/Tauri 专属 Skills 不移植。
5. **环境门禁由 Git/Rust/Node.js/pnpm 改为 Git/Go。** Go 使用连续下界 `>=1.25.0`。
   - 后续说明（本 ADR 追加，不修改上述历史决定）：下界已在 GraphQL 条件资产接入时上调为 `>=1.26.0`。原因是 gqlgen v0.17.95 在自身 `go.mod` 声明 `go 1.26`，而 `graphql=enabled` 的下游必须解析到该版本；在 `GOTOOLCHAIN=local` 下 `go mod tidy` 会直接失败，靠 `GOTOOLCHAIN=auto` 隐式下载工具链又违反本模板「不建立项目内工具链」的约束。因此下界由 `$MinimumGoMinor` / `MIN_GO_MINOR` 单一常量统一上调，不保留双口径。
6. **共享核心的适配器集合由 CLI/TUI/MCP/GUI 调整为 HTTP API/CLI/TUI/MCP。** HTTP API 成为服务型项目的默认适配器，空选择仍默认 CLI。
   - 后续说明（本 ADR 追加，不修改上述历史决定）：接口集合最终收敛为**仅 HTTP API**。CLI 与 TUI 已被彻底移除（对应 Skill 目录已删除），MCP 随后也被彻底移除（`go-add-mcp-adapter` Skill 目录已删除）。`MCP` 已加入下游初始化校验器的禁用能力标记黑名单，生成的下游工程中出现任何 MCP 依赖、适配器目录或文档描述都会被阻断。
7. **模板自身版本重置。** `Version.md`、`release-notes.json`、`.harness/release-context.json` 不继承源模板历史，从新起始值开始。

## 影响范围

- `AGENTS.md`、`README.md`、`Version.md`、`release-notes.json`、`.harness/release-context.json`
- `docs/` 全部文档（方法论分卷照搬、其余按语言替换）
- `scripts/` 验证脚本（`gui_support*`、`rust_comments` 相关校验器移除或改写）
- `.agents/skills/` 全部 Skills

## 理由

- 方法论与语言无关：七层模型、文档职责划分、发布生命周期在 `docs/harness_engineering/` 中未引用任何 Rust 特性。
- 源模板 `docs/CLI_CONTRACT.md` 第 125 行已明确允许其他语言以「等价行为和证据」替代 Rust 基线，本决定是该声明的直接落地。
- Go 与 Rust 同为静态类型、编译型语言，行数门禁的 800 行上限可直接沿用，无需重新校准。
- 删除前端轨与 GUI 专属规则可显著降低 Harness 自身的规则体积与维护成本，符合「Harness 本身也必须遵守 MVP 原则」。

## 风险

| 风险 | 缓解 |
|---|---|
| Go 生态缺少与 Cargo workspace 对等的「包边界强制」机制 | 依赖方向改为包导入闭包检查，由校验器在发布审查时报告 |
| 原 CLI 契约的二进制名派生依赖 Cargo 包名 | 改为由 `go.mod` module 路径与 ASCII 项目标识派生，规则保持等价 |
| 移除 GUI 轨后，未来若需前端仍需重建对应规则 | 保留方法论分卷中语言无关的界面管理原则，实现标准按需新建 |
| 校验脚本 Go 化可能引入与源模板行为不一致 | 保留 `scripts/validate_harness.py` 单一入口与 `unittest` 发现机制，逐校验器对照移植 |

## 验证

- `python3 -B scripts/validate_harness.py` 通过。
- `python3 -B -m unittest discover -s scripts` 通过。
- 校验器正向检查全部必需文件存在，负向注入测试确认缺失时失败。
- 中性脚手架执行 `go build ./...`、`go vet ./...` 通过。

## 恢复或调整标准

- 若 Go 800 行上限在真实下游被反复证明过严，按同一 base 重新校准并在新 ADR 记录依据。
- 若真实下游需要前端适配器，新增独立 `docs/WEB_FRONTEND_STANDARDS.md` 与对应 Skills，不复活已删除的 Tauri 专属规则。
- 若发现某条被判定为「Rust 专属」的规则实际语言无关，按新 ADR 恢复并说明遗漏原因。
