# Go 服务 Harness 工程

> 从真实意图、明确边界到可靠交付，为 Go 后端服务建立可复用、可验证、可持续维护的工程环境。

## 1. 文档目的

这份文档用于指导项目从立项、MVP 实现、真实验收、发布，到后续升级维护的全过程。

它不是某个项目的功能规格，也不是一份要求所有项目采用相同技术栈的模板。它定义的是一套稳定的判断方法：如何把真实需求转化为边界清晰的软件，如何让人和 AI 编码代理准确理解并执行这些边界，以及如何证明软件已经完成并能够继续维护。

本方法特别适合以下项目：

- 为自己、团队或明确用户群体解决一个具体问题。
- 以 HTTP 服务形式交付。本模板当前只覆盖 Go 后端服务，接口固定 HTTP API。
- 由人确定意图和边界，Codex 等编码代理参与设计、实现、测试和维护。
- 希望快速交付，但不接受核心流程不可靠、版本混乱或项目无法接手。

Harness 本身也必须遵守 MVP 原则。项目很小时，Harness 应当简单；只有被实际问题反复证明有价值的规则、文档和自动化，才逐步沉淀为长期基础设施。
